# V5.2: design and authoring overhaul

Based on `Kazumi7884/Professional_website` main commit
`8c9bc11bfe95001d45c60993d9c9e4bf3e6f318b`, retrieved on 10 September 2026.

The site retains its authored content, classic forum author rails, learning
boards, project/resource collections, and individual hobby sections. Its public
output remains HTML, CSS and JavaScript. Existing image and audio files are not
changed by this redesign.

## Three distinct themes

| Theme | Visual decisions |
| --- | --- |
| Balanced · Notebook | Warm paper, ink-blue links and rust accents, serif editorial headings, numbered learning directory, restrained rectangular controls. Default for new visitors. |
| Halo · Field Manual | Slate-blue field panels, sea-glass links and brass signals, technical uppercase headings, angular borders and stronger panel rules. |
| Resident Evil · Case File | Charcoal archive surfaces, aged-ivory text, oxblood warnings, typewriter metadata, serif reading text and case-file rules. |

All themes share a tested minimum 7:1 contrast for the primary, secondary, link
and accent text against the five shared surfaces. This is a palette check, not
a claim that the entire site is certified WCAG AAA. Focus indicators, mobile
reflow, reduced motion, forced colours and print styles remain supported.

Removed V5.1 preferences migrate: Paper and Sunset become Balanced; Terminal
becomes Resident Evil. Halo and Resident Evil preferences remain valid.

## Reading and navigation

- Increased small text sizes and reading space throughout the shared layouts.
- Clearer masthead, active navigation states and homepage project/about links.
- More legible forum rows, numbered learning links and consistent page headings.
- Reading view hides the author rail while retaining the full article.
- Mobile homepage places posts before the secondary author/sidebar material.
- Hobby pages retain their own archive, shelf, chart and journal layouts.
- The 404 page respects a saved theme.

## Writing desk

`python tools/site.py studio` opens a local HTTP service. Visit the printed URL.
The local editor is not exported to `dist/`, and the public `/writing/` page is
only a guide. There is no public write endpoint or required cloud CMS account.

Features: title/summary/date/section/tag fields, editable post catalogue, draft
filter, automatic filenames, formatting buttons, keyboard shortcuts, three
starter outlines, word count, write/preview/split modes, browser recovery,
Markdown download, explicit file saving, and a local build button.

The backend preserves unknown metadata, rejects stale revisions, prevents
path traversal and duplicate filenames, and atomically replaces existing files.
Preview uses the same Python-Markdown extensions as the production build; it
removes active HTML and runs in a sandboxed iframe. It previews the article
body and typography, not every specialised data-driven page layout.

## GitHub projects assessed

Repository pages reviewed on 10 September 2026. These are implementation
decisions, not claims that every listed project was installed.

| Repository | Decision and contribution |
| --- | --- |
| [DOMPurify](https://github.com/cure53/DOMPurify) | Vendored at a fixed commit for local preview sanitisation, in addition to server filtering and the sandboxed preview frame. No CDN request. |
| [Python-Markdown](https://github.com/Python-Markdown/markdown) | Retained existing pinned parser. The editor preview now uses the same extensions as the build, avoiding divergent Markdown rendering. |
| [Jinja](https://github.com/pallets/jinja) | Retained existing pinned template engine. Reused for the local editor shell, keeping executable code and styles in external files. |
| [Primer CSS](https://github.com/primer/css) | Design reference for readable repository-style lists, clear form labels and structural borders. Custom site CSS implements the design; no Primer styles copied or dependency added. |
| [EasyMDE](https://github.com/Ionaru/easy-markdown-editor) | Evaluated beginner-friendly Markdown toolbar, preview and recovery patterns. Implemented a smaller native textarea workflow because this site needs no CodeMirror runtime or icon downloads. EasyMDE is not installed. |
| [Decap CMS](https://github.com/decaporg/decap-cms) | Evaluated a Git-backed publishing interface. Deferred: remote authentication and hosting integration are unnecessary for the current local/OneDrive workflow. |
| [MDXEditor](https://github.com/mdx-editor/editor) | Evaluated rich editing; not selected because V5.1 is not a React/MDX application. |
| [Radix Primitives](https://github.com/radix-ui/primitives) | Evaluated accessible React components; not selected because native controls fit the existing static stack without a framework migration. |

No generated artwork, stock theme package, hosted font or CDN editor is introduced.
DOMPurify is confined to the local writing desk; public-site dependencies are unchanged. The design is authored in the site's own
CSS and templates; the public site downloads no editor bundle.
